# generate_universities_migration.py

Генерирует `src/main/resources/db/migration/data/V14__insert_universities_data_rf.sql` —
data-миграцию Flyway, наполняющую `public.address` / `public.universities` данными по
вузам России (issue #73). Существующую запись ДГТУ (`V2__insert_universities_data.sql`)
не трогает — миграция чисто аддитивная.

## Источник исходных данных

`explore/*.md` — 700 файлов, по одному на вуз/филиал, подготовленных вручную в несколько
проходов (см. историю коммитов) на основе ru.wikipedia.org и открытых справочников вузов
(конкретные ссылки — в разделе «Источники» каждого файла). Каждый файл содержит
структурированные поля: Полное название, Сокращённое название, Город, Год основания,
Тип, Ректор, Адрес, Сайт, Число студентов — поле, где данных не нашлось, помечено как
«информация требует уточнения» и скрипт трактует его как отсутствующее (NULL), а не
пытается его домыслить.

## Регион по городу

Схема требует `address.region` NOT NULL, а в explore/*.md регион явно указан не всегда
(например, «Барнаул» без пометки «Алтайский край» — сам город однозначно определяет
регион). Поэтому регион берётся из справочника `CITY_REGION` в самом скрипте — вручную
составленного соответствия «как записан город в explore/*.md» → «(нормализованный город,
регион)», построенного по всем уникальным значениям поля «Город», встретившимся в
explore/. Это объективные, проверяемые географические факты (какой город к какому
субъекту РФ относится), а не придуманные для конкретного вуза данные.

## Почему в миграции 485 вузов, а не 700

`address.email` в схеме NOT NULL. Точный email вуза (например, приёмной комиссии) known
не для каждого из 700 файлов — во многих explore/*.md поле «Сайт» помечено как
«информация требует уточнения». Придумывать email оттуда, где сайт неизвестен, — не
вариант (см. issue #73, раздел про NOT NULL: «если по вузу нет данных для необязательных
полей — оставлять NULL... если email обязателен, а достоверного адреса нет — такой вуз
либо пропустить, либо использовать email с официального сайта вуза»).

Поэтому:
- для 485 вузов, у которых в explore/*.md указан проверенный сайт, email формируется по
  общепринятому шаблону `info@<домен сайта>` — сам домен при этом настоящий (взят из
  подтверждённого источника), а вот то, что почтовый ящик `info@` на нём действительно
  существует и работает, не проверялось отдельно для каждого вуза;
- 215 вузов без проверенного сайта в миграцию не включены. Полный список — в
  `scripts/skipped_universities.txt` (генерируется этим же скриптом при каждом запуске).
  Чтобы добавить кого-то из них, нужно сначала найти для него официальный сайт (обновить
  соответствующий explore/*.md), а не просто вписать произвольный email.

## Адрес / улица / индекс

Поле «Адрес» в explore/*.md, когда оно известно, обычно в формате
`[индекс, ]г. Город, Улица, д. N`. Скрипт регуляркой ищет «г. Город» и по нему делит
строку на индекс (то, что было до) и улицу (то, что после). Для вузов без известного
подробного адреса `address`/`street` заполняются как `г. {Город}` — это не выдуманный
адрес, а просто менее детальный (город + регион и так корректны).

## Запуск

```bash
py scripts/generate_universities_migration.py
```

Перезаписывает `V14__insert_universities_data_rf.sql` и `skipped_universities.txt`
целиком — при появлении новых explore/*.md с проверенными сайтами (или при исправлении
данных в уже существующих) достаточно перезапустить скрипт.

Если позже добавится вуз в городе, которого ещё нет в `CITY_REGION`, скрипт остановится
с ошибкой `неизвестный город ..., добавьте его в CITY_REGION` — это осознанно, чтобы
регион не заполнялся наугад.
